## Authentication

Data-plane endpoints under `/v1/*` require a project API key in the `Authorization` header.

```bash
Authorization: Bearer pulse_sk_...
```

Control-plane/account endpoints (`/dashboard/api/*` and `/api/auth/*`) are documented in [Dashboard API](/docs/dashboard-api/).

<section id="get-health">
  <h2 class="endpoint-heading"><MethodBadge method="GET" /> <code>/health</code></h2>
  Health check endpoint for readiness and liveness. Public route with no authentication required.

```bash
GET /health
```

<section id="post-v1-traces">
  <h2 class="endpoint-heading"><MethodBadge method="POST" /> <code>/v1/traces</code></h2>
  Ingest OTLP HTTP JSON traces. This is the canonical ingestion path used by current SDKs and CLI integrations.

| Field | Value |
| --- | --- |
| Method | `POST` |
| Body | OTLP JSON object with `resourceSpans` |
| Response | `200 OK`; `partialSuccess` is returned when individual spans are rejected |

```bash
curl -X POST https://your-pulse/v1/traces \
  -H "Authorization: Bearer pulse_sk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "resourceSpans": [{
      "resource": {
        "attributes": [
          { "key": "service.name", "value": { "stringValue": "my-app" } }
        ]
      },
      "scopeSpans": [{
        "scope": { "name": "my-instrumentation" },
        "spans": [{
          "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
          "spanId": "00f067aa0ba902b7",
          "name": "openai.chat.completions",
          "kind": 3,
          "startTimeUnixNano": "1767225600000000000",
          "endTimeUnixNano": "1767225601200000000",
          "attributes": [
            { "key": "pulse.session_id", "value": { "stringValue": "conv-abc-123" } },
            { "key": "pulse.source", "value": { "stringValue": "sdk" } },
            { "key": "pulse.kind", "value": { "stringValue": "llm_call" } },
            { "key": "gen_ai.provider.name", "value": { "stringValue": "openai" } },
            { "key": "gen_ai.request.model", "value": { "stringValue": "gpt-4o" } }
          ],
          "status": { "code": 1 }
        }]
      }]
    }]
  }'
```

</section>

<section id="get-v1-traces">
  <h2 class="endpoint-heading"><MethodBadge method="GET" /> <code>/v1/traces</code></h2>
  Query span-derived trace summaries for the authenticated project.

**Query parameters**

| Name | Type | Description |
| --- | --- | --- |
| `session_id` | `string` | Filter by session ID. |
| `source` | `string` | Filter by `sdk`, `claude_code`, `codex`, `opencode`, or `openclaw`. |
| `provider` | `string` | Filter by provider (`openai`, `anthropic`, `openrouter`). |
| `model` | `string` | Filter by model name. |
| `status` | `string` | Filter by status (`success` or `error`). |
| `date_from` | `string` | Start date (`ISO`, epoch, or `YYYY-MM-DD`). |
| `date_to` | `string` | End date (`ISO`, epoch, or `YYYY-MM-DD`). |
| `limit` | `number` | Maximum number of results. |
| `offset` | `number` | Pagination offset. |

```bash
GET /v1/traces?source=claude_code&status=error&limit=20
```

Returns `{ traces: [...], total: number, limit: number, offset: number }`.

</section>

## Data model

Spans are the canonical records. Traces and sessions are derived at read time:

```text
Session
  Trace (one SDK call or agent turn)
    Span (one operation)
```

SDK summaries include provider, model, token, and cost fields. Agent summaries
include source, span count, tool-call count, and edited-file count. Both use the
same trace detail response and span tree. Standalone `session_start` and
`session_end` spans remain queryable from `/v1/spans` but do not form traces.
