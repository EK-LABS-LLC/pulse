## Latest release

### Developer Experience Refresh

This release focused on making Pulse easier to install, start, update, and operate locally.

#### Highlights

- `pulse-server` now serves the dashboard directly, so the product runs as one app instead of a separate server and frontend setup
- `pulse up`, `pulse down`, `pulse restart`, and `pulse logs` now give the CLI a real local service lifecycle
- `pulse connect` is now the clean path for connecting to an already running shared Pulse instance
- install and upgrade docs now point to one local happy path and one remote/shared path
- reinstalling with the official installer preserves `~/.pulse` data, including local traces and config

#### What changed for local users

Old local setup felt split across multiple steps and terminals.

New local flow:

```bash
pulse setup --local
pulse up
pulse status
```

The dashboard is served from the same local Pulse server:

```text
http://localhost:3000/
```

#### What changed for shared-instance users

If your team already runs Pulse somewhere else, use:

```bash
pulse connect \
  --api-url https://pulse.example.com \
  --api-key pulse_sk_... \
  --project-id my-project
```

That configures the CLI and installs hooks locally without trying to start a server.

#### Upgrade notes

Local/self-hosted Pulse:

```bash
curl -fsSL https://raw.githubusercontent.com/EK-LABS-LLC/trace-service/main/scripts/install.sh | bash -s -- pulse-server
```

Remote/shared-instance CLI users:

```bash
curl -fsSL https://raw.githubusercontent.com/EK-LABS-LLC/trace-cli/main/install.sh | sh
```

Re-running the installer upgrades in place and keeps `~/.pulse` data unless you explicitly purge it.
